## 推荐工作流

采集与证据脚本 → 既有 editor（语义标签、主事件、重要性和重复关系）→ 统一归栏脚本 → 既有选择器 → 既有 writer（卡片及双语概览）→ 内容／语言／栏目脚本校验 → ready 与发布核验。

分类规则交脚本，不新增分类模型或单独付费轮次。同一纯路由函数在选稿前算 section，发稿前再复验；writer 和前端不得重新猜栏目。当前选择器使用 section 做同星级软平衡，若只在最后第一次分类，就必须明确取消或改变该平衡。离线消除本期栏目平衡后，入选集合未变、顺序改变；不能声称本期因此换稿，也不能推断一般情况下不会影响集合。

## 脚本与模型的边界

脚本负责路由优先级、标签结构与层级、机构限额、栏目软平衡、编号映射、重复关系图、日期资格、格式、确定性摘要整句裁剪、语言字段选择、冻结账本及发布核验。部分已经由脚本完成，应复用而不是重写。

模型保留原文语义工作：实际资产、主要事件、主题地域、重要性、跨来源是否同一事件、卡片与概览撰写。脚本不能仅凭全文出现 Texas 就证明是德州市场新闻，也不应将旧关键词 classify 当真值。稳定来自把语义事实与确定性路由分开，而非把所有判断改成大量正则。

现有 deals 同时包含物业交易和公司合并，topic 标签没有主次。若采用上述路由，建议仅增加内部 capital_focus 布尔值，表示主新闻是否为基金／平台层面资本事件，代替模型直接返回 section；不新增通用本体或分类阶段。保留既有四维语义标签，主题地理排除总部、人物和来源所在地。必要时只对非全国地理附短 geo_evidence，脚本检查片段存在；字符串存在不能代替主题语义正确。字段及路由表在实施前明确，再按同一规则开发。

## 最清楚的脚本化节省机会

若 metadata 数字／引用等全部先通过，唯一错误是 SUMMARY_TOO_LONG，而且首句可完整保留，就让脚本保留连续完整句，模型仅修坏卡。首句超过 250、未知引用或错误数字仍走原 metadata 修复；不截句、跳句、忽略尾句错误或放宽门槛。

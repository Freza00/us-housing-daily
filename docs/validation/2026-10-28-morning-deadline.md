## 可靠性修订

1. 每源以成功覆盖的截止点续接，已有游标不被 24／72 小时或 7 天上限替代。首次无检查点时从既有期刊记录或上一工作日初始化；这是迁移／初始化依据，不是历史完整采集证明。
2. 原始材料先落盘再推进水位。模型失败保留 pending；成功后保留截稿后已观察的材料，避免次日 RSS 滚出后漏稿。
3. 已提交的 collection-checkpoint 与忽略 Git 的 collection-cache 分开，恢复时逐源合并水位。以原料 ID／版本指纹判断已处理批次，覆盖同一截止点先刊 A、补采 B 后写稿或推送失败的情况。
4. 原始池保留最近完整材料；推送失败时能从缓存恢复。失败 artifact 放在发布步骤之后，涵盖提交／推送失败，保留 14 天；缓存可能逐出，必要时需恢复 artifact，不能保证所有故障下永不丢数据。
5. 日期／正文尚不足的 ID 不提前标记完成；补齐后可进入候选。源首次扫描为旧档建基线，此后的新 ID／版本即使原发布日期较早也可作为补采，保留原日期并显示补采标记。首次初始化前的所有迟到研究不在完整覆盖承诺内。
6. 积压候选范围与本期覆盖证明分开，旧稿不扩大所有必需来源要证明的时间区间。周月补查的新原料同样持久保存，但不推进日报游标。
7. 记录固定 cutoff、作业开始、采集完成和生成完成时刻；上线时间仍需实际部署验证。

# P0 自动出刊强化完成本地验收，尚未发布

2026-10-30 17:27，北京时间。

本轮按用户“开干”及“先完成代码和测试，暂不启用外部调度与通知”实施。隔离版本和主工作区各通过 205 项测试；已有 29／30 号刊物的离线恢复、发布故障注入与线上内容核验模拟通过。没有提交、推送、部署、付费生成或真实外部调度／通知变更。生产仍使用此前已上线的版本。

## 已实现的恢复行为

| 缺口 | 实现及验收结果 |
| --- | --- |
| degraded 已刊被反复重建 | 完整内容契约校验后的 complete／degraded 同期归档都跳过生成；假 complete 空刊仍拒绝。派生文件损坏转发布修复。 |
| 换 runner／缓存丢失导致重新选稿 | 冻结输入、证据、决策、合格卡片、摘要和 ready 候选，校验身份／规则／模型／散列。冷缓存恢复不补文、不重做编辑。 |
| 共享摘要错误扩大写作失败 | 卡片与摘要分别校验和保存；只请求缺失／坏卡片或摘要。缺卡修好后摘要仍错，也只修摘要，不改写已通过卡片。 |
| 普通 rerun 重置调用上限 | 同版跨运行累计每阶段最多 3 次请求和 660 秒总模型耗时。附件丢失时检查后续可信运行；无法确认账本则禁止新调用，已验证缓存／候选仍可恢复。 |
| 恢复串成另一版本 | 固定 kind／period／cutoff／revision；跨日身份不符停止。指定 revision 的附件缺失／过期／不兼容不得自动换号。单独 force 新建修订，显式工作日手动许可贯穿各阶段，周末仍退出。 |
| 推送失败导致重启生成 | ready 包独立发布，临时克隆只暂存白名单，保护当前工作区。无关远端变更最多刷新重试一次；响应丢失后核对远端提交，永久失败保留候选。 |
| 共享 state 回退或补采丢失 | 从最新远端合并逐源水位，仅消费冻结版本的材料指纹；保留新增原料、正文版本及截稿后材料，包含未提供 content_hash 的变更。 |
| 仓库成功被当作上线成功 | 同时核验生产首页、latest、归档、索引；旧内容、HTTP 失败或超时不确认。收据独立保存，不修改生产 JSON 形成部署循环。 |
| 调度故障不可区分 | 提供只读观察命令，区分未启动、排队、运行、失败、执行未知及仓库成功但线上仍旧；不自动 dispatch 或发送通知。 |

三类生成工作流共用原有并发组，在 prepared／editor／writer 边界上传 14 天附件，阶段附件及缓存步骤设 1 分钟上限和 continue-on-error，缓存保存位于发布之后。Git 身份认证仅传递给临时发布子进程。没有新增依赖、真实密钥或环境配置变更。

- 真实 29 号 57 候选／20 条已刊内容、30 号 70 候选／19 条已刊内容重新通过完整内容契约；ready 恢复无来源或模型调用，隔离输出的首页／latest／归档一致，后续生成跳过。这是已有内容恢复，不是新模型端到端生成。

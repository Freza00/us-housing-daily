# 固定版本恢复与交付核验

恢复先判断本期是否已有合格归档或 ready 候选，再补未完成阶段。来源覆盖不完整仍可是一份合格刊物；普通补偿不为 degraded 反复重新选稿。自动执行沿用北京时间日历守卫；保留已有显式 FORCE_RUN 工作日手动接口，指定 revision 时不丢失该许可，周末始终退出。不启用周月自动跨日补刊，不用历史 PUBLISH_NOW 绕过发布日历。

## 阶段事实源

`state/issues/<kind>/<period>/r<revision>/` 保存 `manifest.json`、`prepared.json`、`editor.json`、`cards.json`、`metadata.json`、`ready.json`。prepared 冻结实际证据、稳定 ID、原始采集增量和前置版本；cards 只保存通过逐稿校验的卡片，metadata 绑定完整入选集合；ready 包含完整合格刊物和发布所需增量。

manifest 记录身份、规则及模型指纹、阶段散列和逐次调用账本。普通重试固定 revision；FORCE_RUN=1 且未指定 ISSUE_REVISION 时才创建新修订。GitHub 新修订号结合 run ID／attempt 分配，允许非连续增长，防止上次附件全部丢失后误用旧号。指定 revision 始终恢复该版，不重置其额度；该版附件缺失、过期或规则不兼容时明确失败，不自动换号，有效同版本地阶段／已刊归档可继续使用。

新刊标记 `editorial_schema: 2`，要求双语概览／主线、脚本归栏一致性；同一归栏函数用于选稿前与成品验证。语义字段和双语契约改变规则指纹，不给旧冻结附件重签、不自动迁移旧刊或已耗尽账本；旧已刊归档保持原契约，英文缺失仅在界面明确提示。

候选增补与有界补文复验只发生在 prepared 冻结之前；快照保留 candidate_preparation 的初始、尝试、合格和排除数量。已经冻结的同版不因少于 20 条重新补选或追加 editor 调用；候选集合变更须遵守新修订、规则散列和账本保护。

中文摘要按规范化后的全部非空白 Unicode 字符计数，目标约 200、上限 250；英文摘要最多 150 个空白分隔词。先独立检查完整双语 metadata；全部摘要句和主线通过内容校验、唯一问题为摘要长度时，保留中英文共同的最长连续完整句前缀并全量重验，坏卡不阻止保存该 metadata；不截句、跳句或删卡，首句超限仍失败。裁剪计数保存于合格 metadata，恢复后进入 `_diagnostics.writer_validation.summary_shortening`；已刊内容校验保持严格，不会在检查归档时自动裁剪。

恢复时先逐卡检查最终规范化形态，并独立检查摘要／主线。失效卡片从可复用集合移除，无效 metadata 记为空；仅修缺口，保留合格卡片、冻结证据及原调用账本。未知／重复卡片编号、集合指纹不符和附件散列损坏仍直接拒绝，不作为普通内容错误忽略。

两阶段各最多 3 次请求，合计模型耗时预算 660 秒。局部纠正与传输重试共用该预算；账本中的未结束请求按预留时长计算。附件缺失或较新的运行已开始模型阶段却没有最终账本时，相关阶段标记 budget_unknown，禁止新请求；已验证缓存和 ready 仍能使用。不要清空 manifest 绕过上限。

恢复合并 pending 时仅去除完整对象完全相同的 source_health 观测，保留不同时间、状态与覆盖区间。生成与发布的输入快照使用同一规则，避免重复恢复使覆盖信息倍增；发布旧冻结候选时只物化精简后的输入文件，不改 ready、payload、阶段散列或调用账本。白名单文件超过 GitHub 100 MiB 限制时在 commit／push 前明确拒绝，须先定位数据膨胀，不通过清账本或重新生成绕过。

阶段附件和交付收据忽略 Git。Actions cache 只加速；恢复下载须通过仓库、分支、工作流、期号、截止点、规则、模型和散列检查。只接收当前仓库 main 的 schedule／workflow_dispatch／repository_dispatch 产物，拒绝 PR 或外部仓库附件。附件过期／损坏须报告，不静默更换网页证据。

## 新日报的写稿池与封版

新日报使用 evidence-refs-v1 编辑协议：原文编号映射随 prepared 冻结，只覆盖实际提供的标题和 1,000／1,200 字符窗口。模型选择主事件与范围证据号，程序绑定原文、核对短地域锚和角色、派生资本属性；只修有问题的语义／证据字段，保留 keep、importance、reason 和去重图。字段未通过不得保存 editor，也不在选稿后静默改成拒稿。范围 non-us 和 unclear 各自保留排除／未验证原因。三次 editor 请求耗尽仍不合格时保留 prepared／诊断，不启用编辑子集封版。冷恢复与最终验收共用绑定检查；任一新协议标记存在时要求顶层和全部卡片协议一致，并且必须保留 writing_policy、美国范围和选稿／写稿门禁。旧刊继续旧契约，旧冻结附件不在新规则下改签。

新日报使用 writing_policy=daily-pool-v1。editor 一次评估完整冻结候选，market_scope=us 才进入写稿池；海外主题必须有美国标的原文方可保留。写稿池最多 26 条，主选为其前 20 条，cards／metadata 的 selected_digest 绑定整个池。最终刊出集合与写稿池分别记录，不通过改变 selected_digest 为临时换稿重开额度。

日报 writer 只输出卡片文本，原文引用由程序绑定。每条数字在实际提供的前 1,800 字符正文及原始标题中核对，百分比核对同值单位。短英文原文节选仅是展示片段，全部中文事实的核查窗口与其区分。周／月报维持原引文 ID 协议。

逐卡保存后，主选好稿优先保留；合格候补按同栏目同资产、同栏目、其余次序递补。补足原主选数即可结束写稿。请求失败且已有合格成果，或进入交付预留点时，允许按门槛不足额封版：原重要稿（4／5）全部保留，有稿栏目不清空，刊出不少于主选 80%，缺口不超过 3 条。结构不明的本次回答不进入卡片缓存，已有可信成果仍可封版；文件或冻结散列故障继续阻断。

metadata 从原合格版本投影到最终刊出集合，引用未刊稿的完整中英句对移除；没有合格速读时 executive_summary 为 null、summary_status 为 unavailable。该例外只适用于新日报，周月报及旧刊仍使用原必填契约。

selection_target 固定为 20，selection_count／selection_shortfall 记录选稿结果；content_target／writing_plan 仍以原主选数记录写稿计划及封版缺口，不能将两个目标合并。补文漏斗按 bucket 保存 readable 和 rejected_reasons；仅 insufficient_evidence 记正文缺口，invalid_date／unverified_update 另列时效未验证，after_cutoff／outside_publication_window 不是正文故障。

writing_plan 保存主选数、写稿池数、暂缓稿及替换关系，来源及栏目计数按最终刊出集合重算。暂缓稿留在原期号诊断与原料快照；封版后普通重试只核验交付，不自动补发或迁移到下一日，不自动创建新的生成额度。

近期事件台账随 prepared 冻结。对标题可识别统计月的通用 Jobs／Employment Report，自动选稿检查同月报告是否已刊；若保留跟进，novelty_evidence 必须是实际输入中的新增就业数据原句，写稿和冷恢复还检查新增数值是否进入成品。独立行业研究和不同统计月不合并。发布器另以远端此前 4 个工作日归档执行同一检查，人工 ready 也不能绕过；失败保留候选，不能清空台账或重签旧冻结附件。此规则不是通用语义去重器。

补文优先桶与最终语义分类分别执行：优先桶只采用明确的标题主体资产。market_evidence 核对原文匹配位置和总部背景范围，合法美国标的不因城市未在名单而拒绝；只截取总部城市也不能作为标的所在地证据。原冻结版仍按原规则恢复，不直接重签规则散列。

## 执行阶段

以下命令展示当前工作日期的操作接口。生成使用已有环境配置；发布 `--push`、工作流 dispatch 和 redeploy 均会改变外部状态，执行须已有对应授权。实际执行记录与已验证范围以 ROADMAP.md 和对应发布验收为准。

```bash
# 用既有密钥环境，顺序执行；同版后续阶段不重新补文或选稿。
PIPELINE_UNTIL=prepared node --env-file=.env scripts/build.mjs
PIPELINE_UNTIL=editor node --env-file=.env scripts/build.mjs
PIPELINE_UNTIL=ready node --env-file=.env scripts/build.mjs

# ready 包已存在时不需要模型凭据；无 --push 只核验生产。
node scripts/publish.mjs daily
node scripts/publish.mjs daily --push

# 只读：当前期生产内容及 GitHub 执行状态；不 dispatch、不通知。
node scripts/check-publication.mjs daily
```

周／月生成入口为 `build-weekly.mjs`／`build-monthly.mjs`，恢复、发布、观察入口的 kind 参数改为 weekly／monthly。NEWS_STATE_DIR 可选择独立恢复状态目录；测试、dry-run 或历史时间仍必须使用隔离 data/state。固定版本命令可同时设置 `ISSUE_REVISION`、`EXPECTED_PERIOD`、`EXPECTED_CUTOFF`，期号或截止点不再匹配当前日历时立即停止。

GitHub 工作流先调用 `restore-issue.mjs <kind>`，用 `GH_TOKEN` 读取附件。手动输入 revision 留空选最新，period 为 YYYY-MM-DD（日报／周报）或 YYYY-MM（月报），cutoff 为 epoch 毫秒。后续步骤传递 prepared 输出的身份，防止排队跨日后变成另一刊。恢复需要 contents:write 和 actions:read；Git 推送采用仅在子进程存在的认证头，不把 token 放到命令参数或候选包。

## 发布失败的处理

| 观察到的状态 | 恢复行为 |
| --- | --- |
| 编辑通过、写稿失败 | 原证据和决策不变，只补写作缺口。 |
| metadata 内容合格、仅摘要超长（可同时有坏卡） | 在内容校验通过后保留连续完整句、全量重验；合格卡片和裁剪后的 metadata 保留，模型只修坏卡。无法保留首句则继续失败／局修。 |
| 卡片通过、摘要有其他错误 | 只修摘要／主线，保留合格卡片；全部 selected 仍须通过最终校验。 |
| ready 已就绪、推送失败 | 只恢复发布，不触发模型；远端无关变更最多刷新重试一次。 |
| 推送响应丢失 | fetch 并确认目标提交是否已在 main，避免再次发布。 |
| 归档已有、latest／索引／首页缺失 | 由同一归档修复派生文件，不重新生成。 |
| 新一期或更高 revision 已发布 | 拒绝旧候选覆盖；共享水位不倒退，新补采材料不删除。 |
| 仓库已更新、生产仍旧／超时 | 返回交付失败并保存收据；可再次只核验，已有配置和授权时可单独 redeploy。 |

交付必须同时匹配生产 latest、本期归档、日期索引，日报再核对首页 initial-data。收据记录内容散列、目标提交、核验时间及逐路由结果，不回写生产 JSON。相同内容重复确认不新增发布提交。

`--redeploy` 只接受配置于 VERCEL_DEPLOY_HOOK 的官方 HTTPS Deploy Hook。没有凭据时明确返回能力不可用，默认工作流不调用。此入口没有本轮真实权限或部署验收，不能据此声称已自动自愈；最终仍要求生产内容匹配候选。

## 截止观察边界

`check-publication.mjs` 区分任务未创建、排队、运行、失败、执行状态未知、任务成功但网站仍旧，以及候选可直接发布。日报 09:00、周报 15:00、月报 16:00（北京）后未核验成功记为 missed；工作流额度预留和只读观察使用同一目标。首次观察已在截止之后，即使网站现已正确，也不会声称此前准时；月报不再返回未定义的 policy_pending。

本轮不注册外部 cron、不发送通知，也不自动 dispatch。现有 GitHub 调度整体未启动时，代码本身不会从外部唤醒；独立承载及告警启用另行落实。下一次生产工作流的阶段上传／恢复、实际 redeploy、连续 10 个工作日 09:00 SLA 都须单独验收。

## 旧规则候选与新代码的发布顺序

修改提示词或校验模块会改变 ruleDigest，不能直接给旧冻结版改散列。地域证据仅有大小写／直弯引号／空白差异而被旧版误拒时，可在兼容旧代码的隔离副本中，将已保存完整回答的该字段还原为实际连续原文，再全量验证短编号、稳定 ID、去重图和标签；只有全部通过才保存 editor 阶段。先重建原请求散列证明候选顺序与回答来源，再刷新远端模型运行和最新账本；本地已有 manifest 的恢复路径会保留本地记录，不能把重复 restore 当成已合并最新 attempts，应用新的空隔离 state 或显式核对。保留原 editor 已耗账本，不使用截断回答，后续 writer 继续按原剩余额度。针对已耗尽模型额度、但可从原回复确定性组装合格摘要的本期候选，应保留冻结输入、卡片和旧账本，用相容旧代码完整验证，再在取得明确授权后走既有发布流程。若同时授权补发与通用代码上线，先核验并发布旧规则候选，再推通用修复；如果远端生成规则已经变化，停止并显式处理新修订迁移，不清账本、不强行跳过发布器的规则变更保护。

周报从北京 05:00 切到完整美东自然周时，同一期号的 cutoff 会变化，旧归档不能当作新窗口已完成；旧 r1 的规则和账本也不能强制复用。正式切换须明确处理过渡窗口：例如 2026-11-02 新窗口比已刊周报多出北京 05:00 至 13:00 的 8 小时，若要补齐必须补采并用明确新修订生成；若保留旧刊，应记录这段缺口，不能默认下一期自然周会自动包含。页面展示旧刊的真实 window，不改其标签伪装成新口径。
